# Art source

3D models are generated by Blender Python scripts, not hand-edited `.blend` files.
The scripts are the source of truth; the exported `.glb` files in `assets/models/` are
build outputs that are committed so the game runs without Blender.

## Build

Blender 5.x, either the app or the `bpy` Python module (Python 3.13):

```bash
# with the Blender app
blender -b -P art_src/blender/build_swarmer.py
# or with the Python module
pip install bpy==5.3.0
python art_src/blender/build_swarmer.py
# add a turntable-style preview render (Cycles, CPU) to any folder
python art_src/blender/build_swarmer.py --preview /tmp/swarmer_preview
```

Then open the project in Godot (or run `godot --headless --path . --import`) to reimport.

## Conventions

- Meters, Z up, the bug faces +Y in Blender. The glTF exporter converts this to Godot's
  Y up with the bug facing -Z, which is what `enemy.gd` assumes. Origin on the ground.
- Two material slots: `Chitin` and `Glow`. The `.glb.import` file remaps them to
  `assets/materials/*.tres`, so colours are tuned in Godot, not Blender.
- Rigid skinning: each part is weighted 100% to one bone.
- Clips: `idle` and `walk` loop (set in the `.glb.import`); anything else is a one-shot.
  `walk` is one stride cycle; `enemy.gd` scales its speed by ground speed
  (`walk_anim_speed`, `max_anim_speed` on the enemy scene).

## Files

| File | What |
|---|---|
| `blender/kit.py` | Shared parts kit: limb tubes, chitin blades (plates, spikes, claws, mandibles), ellipsoids, orbs; rig, skinning, keyframe, export and preview-render helpers |
| `blender/hexapod.py` | Shared six-legged walker: leg layout, leg meshes and bones, tripod walk gait, idle fidget |
| `blender/build_props.py` | Set-dressing props after the concept mockups (AC unit, cabinets, switchgear, server rack, console, wall panel, door, tank, container, eggs, floor vent, planter, lockers...), plus the starship set (ship pillar, hazard crate, hull window, supply pod) and the foundry set (crucible, smoke stack, furnace pillar, ingot stack). One GLB each in `assets/models/props/`; `--only a,b` builds some, `--preview DIR` renders Cycles stills |
| `blender/build_swarmer.py` | Swarmer: shingled shell, amber eyes and glow seams. ~2.5k tris, 17 bones. Clips: idle, walk, attack |
| `blender/build_burster.py` | Burster draft: lime sac with chitin veins under an armoured front shell; idle, walk, swell clips. **Not used in game**: the stand-in is kept until the model is redone (likely from an image-to-3D mesh). `burster.gd` already plays `swell` if a model provides it |

## Hooking a model into an enemy

Instance the `.glb` under the enemy's `Visual` node and remove the primitive meshes.
Hit flash and tier scaling work on anything under `Visual`. If the model has an
`AnimationPlayer`, `enemy.gd` plays `idle`/`walk` automatically and `attack` on a
successful bite (`play_anim_oneshot()` is there for special enemies).

## Generated models (Higgsfield / Meshy)

Some models start as AI image-to-3D output instead of a script. These are the exception to
"the scripts are the source": the source is the generated file, and a script cleans it up.

**The hunter** (player character, `assets/models/hunter/`):
- `hunter.glb`: 31k triangles, 24-bone humanoid skin, 1024 px textures (colour, metal/rough,
  normal; WebP inside the GLB). Clips: `idle`, `run_forward`, `run_back_left`, `run_back_right`,
  `strafe_left` (mirror it for right), `walk_back` (these loop), and `roll`, `sword_combo`,
  `sword_parry`, `reload`, `hit`, `death` (one-shots). The roll, combo, parry, hit and reload stay
  in place: the game moves the character.
- `hive_rifle.glb`, `chitin_blade.glb`: the weapons, decimated to about 5k and 4k triangles.
- Built by `blender/import_hunter.py SRC_DIR` from the raw downloads listed (by job id) in
  `higgsfield/hunter_jobs.tsv`. The concept sheets they came from are the hunter mockups.
- Every animation clip was generated as a separate re-rig of the same mesh, and those skeletons
  differ slightly (a few cm, a few degrees of bone roll). The script retargets each clip onto the
  first rig by bone name (each bone's armature-space rotation from rest, hips scaled by height),
  so all clips share one skin. To add a clip: generate it on the same model, save it as
  `SRC_DIR/clips/<name>.glb`, add it to `LOOPS` or `IN_PLACE` if needed, and rerun.
- `DERIVED` in the script cuts game-speed pieces out of library clips (`swing_1..3` from the
  combo, `roll_fast`, `hit_quick`, `death_fall`) and mirrors `strafe_left` into `strafe_right`.
- In game she is `scripts/player/hunter_body.gd`, created by `player.gd` (`use_hunter`; off
  brings back the old placeholder body).
